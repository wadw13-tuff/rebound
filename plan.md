# Rebound MVP

## Approach and assumptions
The supplied detailed brief authorizes implementation without further questions. Use Next.js App Router, TypeScript, Tailwind CSS, Prisma with SQLite, and Vitest. Build data model, deterministic engine/tests, API routes, Claude adapter, then UI. Anonymous browser identity replaces sign-in for this MVP; each browser gets an isolated user via an opaque HttpOnly cookie. Kilograms, local calendar dates supplied by the client, and a configurable RPE target defaulting to 8 are assumed. Fresh visitors can inspect an explicitly labeled example plan before completing four-step onboarding; example activity is never persisted as personal history. No Anthropic key is required; deterministic explanations and swaps always work. SQLite is for local/Preview only: durable public deployment requires Postgres and cookie/security hardening. No public deployment is requested.

## Architecture and structure
`prisma/schema.prisma` holds User, Profile, Program, Session, Exercise, SetLog, CheckIn and PlanChange. Session prescription and structured change snapshots are serialized JSON strings for SQLite/Postgres portability. `lib/domain.ts` defines shared types; `lib/library.ts` has at least 40 tagged approved exercises and explicit swap lists; `lib/templates.ts` produces four-week 2–5-day plans from three templates. `lib/engine.ts` is pure, event-driven, immutable and unit-tested. Safety takes precedence, reduction factors use the most conservative simultaneous factor rather than compound accidentally, volume rounds to at least one set, and date placement obeys blocked days, one session/day and at most three consecutive days. `lib/llm.ts` calls Claude only for explanation and selecting an ID from already-filtered swap candidates, never planning quantities; invalid swaps retry once then deterministic fallback. `lib/service.ts` orchestrates Prisma transactions, overdue detection, engine events and approved LLM choices. Next.js `app/api` routes validate all inputs and scope records to the cookie user. `components/` holds application shell, onboarding, dashboard, workout, check-in, schedule and history. `public/` serves application-owned PWA manifest/icons/service worker and route manifest. Cached page shell plus local draft storage support temporary connectivity loss; API calls are not cached and LLM outages require no special user action.

## Selected design
Design movement: contemporary editorial wellness with soft utilitarian controls. Principles: a quiet hierarchy, compassionate microcopy, clear actionable feedback, generous touch targets. Color philosophy: warm ivory removes clinical harshness, dark forest anchors text, terracotta signals forward motion without urgency, sage communicates recovery. Layout: persistent narrow left rail on desktop, asymmetric main workout column plus compact contextual sidebar; mobile stacked content with bottom navigation. Signature elements: rebound loop mark, peach adaptive-plan cards, a seven-day capsule timeline. Interaction: every actionable button produces navigation, a state update or a clear dialog; drag moves have an accessible click alternative. Animation: 160–220ms opacity/translate transitions, restrained hover lift, no motion under prefers-reduced-motion. Typography: Manrope for headings and body, strong 32–40px greeting, 20–24px section headings, 12px uppercase tracked labels, tabular workout numerals. Brand essence: flexible strength training for lives that do not follow a fixed calendar. Personality: grounded, encouraging, adaptable. Voice: 'Your plan moves with you.' and 'A little lighter. Still moving forward.' Wordmark: bold rounded lowercase rebound beside a bent loop-arrow glyph. Signature color: burnt coral #D96845.

## Scope and constraints
All requested engine rules, structured changes, safety referrals, API error fallbacks, four-step onboarding, logging/rest timer, schedule drag/drop and trip/sick blocks, history chart, three starter templates and exercise seed library are required. No medication advice, medical diagnosis or sharp-pain workarounds. Safety pauses persist until the user explicitly clears them after clinician review. Exclude native apps, wearables, social, payments and nutrition. Development listens on 0.0.0.0:3000. Docker setup is included for self-hosting with a durable SQLite volume or an adapted Postgres schema.
