# Rebound outcomes

- [x] Data and starter programs: Prisma SQLite schema portable to Postgres with User, Profile(goal,days,equipment,experience,limitations), Program, Session(date,status planned/done/skipped/moved), Exercise, SetLog, CheckIn, PlanChange; at least 40 tagged exercises (movement pattern, loaded areas, equipment), explicit approved swaps, and three templates: 3-day full-body, 4-day upper/lower, 2-day minimal; generate four-week plans for 2–5 training days.
- [x] Deterministic pure TypeScript adjustment engine with Vitest covering every rule and edge cases, including simultaneous triggers and overlapping trip dates: one miss moves to next free day same load; 2+ weekly misses restart rounded sets×0.8 with weights unchanged; 7–13-day gap uses 85% last working weights; 14+ gap uses 70% volume and weights, restart flag; two consecutive energy 1–2 check-ins reduce next volume 20%; mild area pain swaps only affected exercises from approved list; sharp pain/numbness/trauma stops planning area, clinician referral and no workaround; travel/sick dates removed and remaining sessions shifted/compressed max one/day and max three consecutive days; two successful RPE-appropriate sessions progress smallest standard weight increment. Every change {type,reason_code,affected_sessions,before,after}.
- [x] API persistence: Next routes validate inputs, isolate browser users and persist onboarding, generated program, set-by-set weight/reps/done/skipped logs, energy/pain check-ins, availability, safe schedule moves, and change snapshots/explanations. Missed sessions automatically detected on current-date state refresh; adjustment triggers are idempotent and safety overrides progression.
- [x] Narrow Claude layer: exactly explanation and approved whitelist-ID swap selection; JSON-only safe parse; swaps validate and reject/retry once then first rule match; never invent exercises/change weights/diagnose; no blaming or word 'failed'; template explanations and approved swaps keep app fully usable without a key or on API failure.
- [x] Safety: one-time 'Rebound is not medical advice' disclaimer; sharp pain, numbness, chest pain, dizziness, recent injury/trauma trigger clinician referral and pause affected area (global pause when no area/systemic symptoms); no workarounds or medication guidance; persistent pauses do not silently disappear.
- [ ] Mobile-first responsive Tailwind UI and installable application-owned PWA: 4-step onboarding(goal,2–5 days,equipment,experience,limitations) under 2 minutes; onboarding and first set log under 3 minutes; Home today/week/visible friendly change card; Workout set-by-set logging and rest timer; Check-in energy 1–5 and none/mild/sharp plus optional area; Schedule week view drag-to-move, accessible move alternative, trip/sick ranges; History completed sessions and per-lift chart. Two misses visibly show 80% restart; sharp pain never presents workaround. All navigation and primary controls function.
- [x] Delivery: short architecture/file structure, full working code, README setup and environment variables, assumptions and suggested next steps, test/typecheck/build evidence, a read-only implementation validation agent, managed checkpoint and source-code archive. The later requested scope adds an optional Rebound Plus Lemon Squeezy subscription, signed/idempotent webhook fulfillment, payment history, and a system/light/dark theme switch.
