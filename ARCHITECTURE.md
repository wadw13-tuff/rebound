# Rebound architecture

Rebound uses **Next.js App Router, TypeScript, Tailwind, Prisma/SQLite and Vitest**. The mobile-first UI is a small set of route-driven client screens. A browser-scoped anonymous HttpOnly cookie isolates each user without introducing a sign-in step. The first visit shows clearly labeled, non-persistent example data; onboarding creates a real four-week program.

The request path is `screen → /api/state → Zod validation → identity-scoped service → pure adjustment engine → transaction`. `GET /api/state` loads the active plan and detects overdue sessions. `POST /api/state` handles onboarding, per-set logging, session preparation, check-ins, schedule moves, time-away ranges, standalone safety reports, and explicitly clinician-reviewed returns. Health readiness is exposed separately at `/api/health`.

`prisma/schema.prisma` contains User, Profile, Program, Session, Exercise, SetLog, CheckIn and PlanChange. Prescriptions and change snapshots are serialized strings so the schema can migrate to Postgres. Session miss markers preserve the original calendar week, and a preparation flag makes return-from-gap adjustments idempotent. Original set-count baselines prevent accidental compounding of reductions. Standalone safety check-ins belong to the user and never falsely complete a future workout.

`lib/engine.ts` is pure and immutable: safety overrides swaps and progression; fixed rules govern quantities and schedules. The library contains 44 tagged exercises and explicit approved swaps. Templates generate four weeks from the 2-day minimal, 3-day full-body and 4-day upper/lower starters, with a 5-day adaptation. Scheduling reserves one session per date and at most three consecutive training days.

`lib/llm.ts` can only rewrite an approved explanation or choose an already-approved exercise ID. Every response must be valid JSON. Swap IDs are validated, retried once and otherwise replaced by the first rule match. All provider errors fall back to deterministic copy and choices. Medical referrals are fixed text, not generated advice.

`components/ReboundApp.tsx` contains the shell, home, onboarding, schedule and program overview. `TrainingViews.tsx` contains the logger, timer, check-in and actual-log progress chart. `SafetyNotice.tsx` makes persistent pauses visible and requires explicit clinician-review confirmation before a conservative restart. `BillingView.tsx` and `lib/billing.ts` implement a single Rebound Plus subscription through Lemon Squeezy: server-created hosted Checkout, the provider customer portal URL captured from subscription webhooks, signed `/api/lemonsqueezy/webhook` verification, minimal entitlement/payment records, and processed-event idempotency. Card details never enter the app. `ThemeToggle.tsx` cycles system/light/dark and persists the preference locally and, for onboarded users, in Profile. PWA files are application-owned; static shell caching and local drafts support temporary interruptions, but offline server mutations are not queued.

For setup commands, environment variables, assumptions and production next steps, see `README.md`. The deliverable is suitable for local and Preview evaluation. Before public use, migrate to durable Postgres, add authenticated account recovery and production security controls, and have the exercise library and safety policies clinically reviewed. SQLite in a temporary published container is not durable storage.
